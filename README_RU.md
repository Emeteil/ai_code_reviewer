# AI Code Reviewer

[English](README.md) · **Русский**

GitHub Action, который автоматически ревьюит каждый Pull Request агентной LLM
([opencode](https://opencode.ai)) и оставляет структурированный комментарий.

> **Полностью бесплатно — без регистрации и API-ключей.** opencode даёт несколько
> моделей бесплатно, без регистрации и ключей. Поэтому подключить ревьюер к
> своему проекту можно абсолютно бесплатно: просто добавь workflow, никаких
> секретов не требуется.
>
> ⚠️ **Не рекомендуется для чувствительного кода.** Бесплатные модели могут
> логировать отправляемые данные и обучаться на них. Не используй их для
> enterprise/проприетарного кода и всего, что чувствительно к попаданию в
> обучающие датасеты. Для таких проектов не используй версию из стора
> (`uses: Emeteil/ai_code_reviewer@v1`), а скопируй `action.yml`/workflow к себе и
> адаптируй под свою self-hosted модель. В корпоративной среде также рекомендуется
> использовать внутреннее зеркало npm (и прочие внутренние зеркала/прокси) вместо
> публичного реестра.

## Возможности

- **Структурированный ответ**: резюме → 🔴 критические → 🟡 некритические → 🏛️ архитектура → ✅ что хорошо.
- **Агентный доступ к репозиторию**: ревьюер читает соседние файлы для контекста,
  но комментирует **только дифф** (утверждённый код не трогает).
- **Контекст PR**: в промпт передаются заголовок, описание, сообщения коммитов и
  список изменённых файлов.
- **Память между прогонами**: предыдущее ревью этого же PR подаётся в контекст —
  агент отмечает исправленное и не повторяется. Комментарии других ревьюеров
  складываются в `pr-comments/others/`, откуда агент читает их по надобности
  (например, если автор объясняет, *почему* код сделан именно так).
- **Проверка Code Style** из файла контекста проекта.
- **Один комментарий на PR**: при новых пушах существующий комментарий обновляется,
  а не плодятся новые (переключается через `comment-mode: create`).
- **Полностью настраивается** через входы Action с разумными значениями по
  умолчанию — работает «из коробки».
- **Промпты вынесены в отдельные файлы** — правь их без касания YAML.

## Быстрый старт

Добавь в свой репозиторий workflow `.github/workflows/ai-review.yml`:

```yaml
name: AI Code Review

on:
  pull_request:
    types: [opened, synchronize, reopened]

permissions:
  contents: read
  pull-requests: write

jobs:
  ai-review:
    runs-on: ubuntu-latest
    steps:
      - uses: Emeteil/ai_code_reviewer@v1.0.2
        with:
          language: Русский
          # Нужен, только если модель требует ключ провайдера:
          opencode-api-key: ${{ secrets.OPENCODE_API_KEY }}
```

Готово — на каждый PR появится комментарий с ревью. См. [`examples/ai-review.yml`](examples/ai-review.yml).

## Входы (inputs)

Все входы опциональны.

| Вход | Назначение | По умолчанию |
| --- | --- | --- |
| `model` | Модель opencode | `""` (модель opencode по умолчанию) |
| `language` | Язык ответа ревью | `English` |
| `max-diff-bytes` | Лимит диффа в промпте (байты) | `40000` |
| `main-prompt-file` | Путь к основному промпту (пусто = встроенный `prompts/main.md`) | `` (встроенный) |
| `project-context-file` | Путь в твоём репо к контексту проекта; пропускается, если файла нет | `.github/ai-review/project-context.md` |
| `extra-instructions` | Доп. разовые инструкции в промпт | `` |
| `title` | Заголовок комментария | `🤖 AI Code Review` |
| `comment-mode` | `update` (обновлять один) или `create` (новый на каждый прогон) | `update` |
| `include-previous` | Подавать прошлое ревью этого PR в контекст | `true` |
| `include-comments` | Складывать комментарии других ревьюеров в `pr-comments/others/` | `true` |
| `snippets-dir` | Папка в твоём репо, переопределяющая встроенные `prompts/snippets/*.md` (пофайлово; отсутствующие берутся из встроенных) | `` (встроенные) |
| `comment-marker` | Скрытый маркер комментария; смени, чтобы запускать несколько независимых ревьюеров на одном PR | `<!-- ai-code-review -->` |
| `opencode-args` | Доп. CLI-аргументы для `opencode run` | `` |
| `fail-on-error` | Падать, если вызов модели не удался, вместо публикации fallback-комментария | `false` |
| `opencode-api-key` | Ключ провайдера opencode (если модель требует) | `` |
| `github-token` | Токен для чтения данных PR и публикации комментария | `${{ github.token }}` |

## Контекст проекта (рекомендуется)

Чтобы ревью учитывало стек, Code Style, архитектуру и то, что игнорировать —
скопируй [`prompts/project-context.example.md`](prompts/project-context.example.md)
к себе в репо как `.github/ai-review/project-context.md` и заполни. Action подхватит
его автоматически. Можно указать другой путь через `project-context-file` или
задать его пустым, чтобы отключить.

## Как это устроено

Action собирает единый промпт из нескольких частей:

```
=== INSTRUCTIONS ===      (встроенный prompts/main.md, {{LANGUAGE}} подставляется)
=== EXTRA INSTRUCTIONS === (вход extra-instructions, если задан)
=== PROJECT CONTEXT ===    (project-context-file, если есть)
=== PR / GIT CONTEXT ===   (заголовок, описание, коммиты, изменённые файлы)
=== PREVIOUS AI REVIEW === (прошлое ревью этого PR, если есть и включено)
=== OTHER PR COMMENTS ===  (указатель на pr-comments/others/, если есть)
=== DIFF ===               (усечённый дифф PR, merge-base..head)
```

Отдельный шаг выгружает прошлое ревью в `pr-comments/previous_ai_review.md`, а
комментарии других участников (обсуждение, ревью, inline-замечания) — в
`pr-comments/others/` (по файлу на комментарий). Затем `opencode run` выполняется в
корне репозитория — агенту доступны и эти файлы, и весь репозиторий — и результат
публикуется/обновляется как комментарий к PR.

## Кастомизация промптов

- `prompts/main.md` — роль ревьюера, правила и формат ответа. Обычно менять не
  нужно. Плейсхолдер `{{LANGUAGE}}` подставляется из входа `language`.
- `project-context.md` (в твоём репо) — всё специфичное для твоего проекта.
- `prompts/snippets/*.md` — маленькие инъектируемые тексты (заметки к секциям,
  футер комментария, fallback-сообщения). Любой из них переопределяется пофайлово
  через `snippets-dir`.

Чтобы переопределить встроенный основной промпт, укажи `main-prompt-file` на файл
в своём репозитории.

## Заметки

- **Права**: workflow'у нужны `pull-requests: write` (публикация комментария) и
  `contents: read`.
- **Ключ API**: с бесплатной моделью по умолчанию не нужен — часть моделей opencode
  работает без регистрации и ключей. Для других/платных провайдеров передай
  `opencode-api-key` из секрета.
- **`language`** принимает любое название языка: `English`, `Русский`, `Deutsch`.
